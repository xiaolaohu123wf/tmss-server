# TMSS 姚家平车辆智能监管平台 — 商务宣传方案

> **系统全称**：Truck Monitoring System Simplify（TMSS）  
> **典型场景**：水利枢纽、土方运输、钢便桥与窄路施工等工程车辆与船舶协同监管  
> **文档定位**：面向业主与决策方的功能与价值说明；技术实现细节以 `ARCHITECTURE.md`、`DATABASE.md`、`详细说明.md` 等工程文档为准。

---

## 一、方案概述

TMSS 将 **车载终端（GPS + 4G + 语音 + 本地显示）** 与 **云端平台（实时监管、轨迹与作业分析、告警留痕、权限分级）** 打通，实现「看得见、算得清、喊得到、查得到」的土方与运输作业数字化管理。

本方案在既有产品设计基础上，突出 **功能实现清单**、**规模与设备配置思路** 及 **部署与费用预算框架**，便于立项汇报与招标响应。

---

## 二、规模与资源配置（数量计算思路）

下表为 **配置层级的示例结构**，具体台套数由业主根据标段、运力与冗余策略确定；平台侧支持按车队、按设备扩展，无人工上限瓶颈。

| 类别 | 配置说明 | 典型用途 |
|------|----------|----------|
| **车辆终端** | 按实际参运车辆数配置，一车一终端（含定位、通信、播报、可选小屏） | 运料趟数统计、超速/围栏、作业区识别、大屏定位 |
| **船舶终端** | **首尾各 1 套**（进入/离开水域、停泊与会让等场景分别覆盖） | 船舶定位、防碰撞预警相关数据接入与记录 |
| **备用机** | 建议按车辆端 **5%～10%** 或不少于 **1～2 台** 冗余 | 故障换机、抽检标定，减少停工待件 |

> **说明**：船端若与车端共用同一 TMSS 协议与账号体系，可在后台按「设备 — 车辆/船舶载体」绑定管理；绑定与留痕规则与 `FEATURE_FLEET_CAPTAIN_V2.md` 中车队隔离设计一致。

## 三、核心功能实现清单（重点）

以下为本项目 **必须向业主交付的能力主线**；与 `详细说明.md`、`DEVPLAN.md` 中阶段成果及持续迭代项对齐。

### 3.1 运料趟数计算及高精度轨迹定位分析

| 能力项 | 实现要点 |
|--------|----------|
| 高频轨迹 | 终端按约定频率上报定位；服务端 **TCP 长连接** 接收，**PostgreSQL 分区表** 持久化，支持历史回放与统计。 |
| 轨迹分段 | 按 **装料 / 卸料 / 重载运输 / 空载运输 / 停车闲置（及未知）** 等状态自动分段（见 `ARCHITECTURE.md` 作业状态机），支撑趟数可归因分析。 |
| 停车切段 | **驻留阈值 10 分钟**（可调策略）：超时进入新的一段轨迹语义，便于区分连续作业与非作业停车。 |
| 地图展示 | 管理端与大屏基于 **高德地图 GCJ-02** 展示；原始点存 WGS-84，展示时转换，满足国内合规与视觉精度。 |

### 3.2 超速、超界等危险行为分析与报警记录

| 能力项 | 实现要点 |
|--------|----------|
| 分域限速 | 后台配置 **地理围栏 + 精细化速度阈值**，不同区域不同标准。 |
| 实时告警 | 触发条件后 **下行短指令**，MCU 驱动 **语音播报**（如超速、越界类提示）；服务端 **事件入库**，可追溯。 |
| 留痕合规 | `event` 等表完整记录告警类型、时间、关联车辆与围栏，支持与 `ARCHIVE.md` 归档策略衔接，便于审计。 |

### 3.3 船舶防碰撞预警记录

| 能力项 | 实现要点 |
|--------|----------|
| 多目标态势 | 船端首尾设备上报位置与航向相关数据后，平台侧可叠加 **相对距离、会遇趋势** 的展示与预警逻辑（具体算法与阈值按海事/项目规范配置）。 |
| 记录与追溯 | 预警产生即 **记录事件**，可与历史轨迹联动查询，便于事故复盘与调度优化。 |

### 3.4 钢便桥过车调度

| 能力项 | 实现要点 |
|--------|----------|
| 单边桥 / 窄路 | 与 **「来车语音调度」** 能力结合：后台可下发 **调度类指令**，终端播报 **优先通行 / 停车等待**，并 **记录下行指令与关键状态**。 |
| 协同规则 | 支持按标段、单向通行窗口、车队优先级等业务规则扩展；与围栏、禁行时段等配置联合使用。 |

## 四、终端与平台联动功能清单（设备设计对应表）

下列条目与 `详细说明.md` 中原始需求一一对应，体现 **车端 — 云端 — 大屏** 全链路交付范围。

| 序号 | 能力描述 | 实现形态摘要 |
|:----:|----------|----------------|
| 1 | **会车语音提醒**（急弯等盲区来车） | 基于相对位置与会车逻辑触发播报 + 可配置规则；事件可留痕。 |
| 2 | **单边桥、窄路来车调度** | 语音调度指令 + **后台调度与通行记录**。 |
| 3 | **超速语音 + 后台记录** | 分区域限速阈值 + **ws** 类指令链路 + **事件查询**。 |
| 4 | **作业区域与任务** | 后台维护 **装料区 / 卸料区** 等围栏；**统计作业次数与作业内容**。 |
| 5 | **作业状态识别** | **装料中、卸料中、重载运输、空载运输** 为核心业务态；辅以 **未知、停车闲置** 等完整状态机，与大屏配色一致。 |
| 6 | **限行区域 / 私自离开报备**（可选） | 限行围栏 + 报备策略；告警与留痕可按 **业主需求** 裁剪。 |
| 7 | **设备 — 车辆 — 人员绑定** | 后台绑定/解绑；车队隔离与权限见 **车队管理员 V2 规格**。 |
| 8 | **大屏实时监管 + 长期存储** | **SSE 实时推送**；定位、速度、海拔等展示；历史数据 **持久化 + 冷热归档策略**（`ARCHIVE.md`）。 |
| 9 | **权限分级** | **最高管理**可览全局；**车队管理员**仅本车队车辆、成员与设备管理。 |
| 10 | **禁止运营**（区域 + 时段） | 后台规则 + 前端语音提醒 + **违规运营记录**。 |
| 11 | **装/卸料区与最短驻留** | 围栏类型 + **装料 / 卸料最短驻留时间（秒级配置）**，用于确认有效作业。 |
| 12 | **停车切段** | **10 分钟** 驻留阈值策略，超时进入新轨迹语义段。 |
| 13 | **喇叭功率** | 当前硬件 **不提升功放功率**，以现有音量设计语音策略（文案简短、重复间隔合理）。 |
| 14 | **死机续传与稳定性** | 终端侧网络恢复后续传；服务端 **断线重连与缓存点** 设计；固件与硬件迭代提升鲁棒性。 |
| 15 | **车载小屏** | **时间、天气、温度、超速/越界提示动画、实时速度** 等本地展示（与 `TECHSTACK.md` 天气 API 等能力配合）。 |

## 五、技术架构亮点（便于技术评审一页纸）

- **后端**：Python 3.11 + **FastAPI**，HTTP（8900）与设备 **TCP（8901）** 同源异步架构。  
- **数据**：PostgreSQL + **按月分区** 高频点位；Redis 会话与缓存；事件与轨迹可归档。  
- **前端**：Vue 3 + 高德地图 + ECharts；大屏 **SSE** 实时车流。  
- **安全合规**：会话鉴权、车队数据隔离、操作留痕可追溯。

详见 `TECHSTACK.md`、`ARCHITECTURE.md`。
