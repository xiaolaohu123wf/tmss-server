# 姚家坪水利枢纽土方运输智能管控系统

> **英文名**：Truck Monitoring System Simplify（TMSS）  
> **应用场景**：水利枢纽工程土方运输车辆全生命周期监控管理  
> **系统入口**：`http://<服务器IP>:5173`（开发）或 `http://<服务器IP>`（生产，经 nginx）  
> **默认管理员账号**：`admin` / `admin123`（首次启动自动创建，建议上线前修改密码）

---

## 背景与功能介绍

为实现土方运输车辆全流程管理监控，设计并集成 GPS、音频模块、4G 模块与 ESP32 终端采集硬件，实时采集车辆定位信息，并与服务器交互数据，终端可进行语音播报。

具体功能如下：

1. 会车语音提醒（如急弯等视野盲区来车提醒）。
2. 单边桥、窄路来车语音调度与后台记录（支持优先通行与停车等待指挥）。
3. 超速语音提醒与后台记录（可自由划定区域并设置精细速度阈值）。
4. 后台标记作业区域与任务（装料区、卸料区），识别并统计作业次数与作业内容。
5. 识别四种作业状态（上料，下料，运输，空载，未知）。
6. 后台标记限行区域与限行地点；车辆私自离开且未报备时，前台自动告警并后台留痕（可选，视业主需求）。
7. 后台支持设备与车辆、驾驶员的绑定与解绑。
8. 大屏实时查看车辆定位、速度、海拔等信息，并永久存储。
9. 后台设置权限分级：最高权限可查看所有定位；车队管理员可查看车队定位并管理车队成员信息（与第 6 条相关）。
10. 后台可按区域和时间设置车辆禁止运营；前台语音提醒并记录违规运营信息。
11. 后台设置装料区、卸料区，以及装料最短时长、卸料最短时长。
12. 停车时长阈值为 10 分钟，超时视为下一段轨迹。
13. 硬件约束：喇叭声音受功率限制，暂不增大。
14. 支持设备死机后的后台数据传输，并提升硬件稳定性。
15. 车载小显示屏显示内容：时间、天气预报、温度、超速/越界动画、实时速度。

## 功能设计实现
### 边缘通讯功能
基于 TCP 数据透传能力，边缘端设备端按“首次注册 + 高频定位 + 低频全量状态”进行实时上报。

<details>
<summary>点击展开伪代码</summary>

```text
初始化:
  等待系统稳定启动(约15秒)
  cycle = 0
  prevNetReady = false
  hasRegistered = false

循环(每1秒执行一次):
  cycle += 1
  netReady = 当前网络是否可用
  gpsFixed = 当前GPS是否已定位

  # 1) 首次联网注册（仅开机后第一次网络可用时发送）
  如果 netReady 从 false -> true:
    如果 hasRegistered == false:
      发送注册包 {type: "register", deviceId}
      hasRegistered = true
    否则:
      跳过注册（重连不重复注册）
  prevNetReady = netReady

  # 2) 高频定位包（1秒一次，仅在GPS已定位时）
  如果 gpsFixed:
    构建定位简包 {
      type: "gps",
      deviceId,
      lat, lng, speed, altitude
    }
    如果 netReady:
      发送定位简包

  # 3) 低频全量包（GPS未定位:30秒；已定位:150秒）
  fullInterval = gpsFixed ? 150 : 30
  如果 cycle >= fullInterval:
    cycle = 0
    构建全量状态包 {
      reportTime,
      signalStrength,
      deviceId,
      iccid,
      batteryVoltage,
      gps: {
        isFixed,
        (若已定位则附加 lat/lng/speed/altitude/gpsTime/variation)
      },
      lbs: {lng, lat}
    }
    如果 netReady:
      发送全量状态包
```

</details>

<br>

逻辑要点：

- 注册包只发一次，避免网络抖动导致重复注册与轨迹切断。
- 定位简包高频发送，用于实时轨迹展示，字段尽量精简以节省流量。
- 全量包低频发送，用于设备健康状态与补充定位信息（含 LBS 兜底）。
- 所有上报都受网络状态门控：离线或4g模块故障时不发送，待网络恢复后继续周期上报。

### 服务端数据交互

本方案在设备与平台之间建立 **TCP 长连接**，做数据透传：服务端可对已连线的设备下发短指令；报文经 **4G 模块** 透传至 **MCU**，由 MCU 解析后驱动语音播报等动作。

**电气约定（MCU 端 GPIO）**

- 输出为推挽；**低电平为有效**（拉低即触发/播报逻辑），**上电后初始为高电平**。

**服务端指令与语音内容**

| 指令 | GPIO | 说明 |
| --- | --- | --- |
| `gm` | 8 | 早上欢迎语 |
| `ga` | 9 | 下午欢迎语 |
| `gn` | 10 | 晚上欢迎语 |
| `ws` | 11 | 超速提醒 |
| `wa` | 12 | 越界提醒 |
| `vs` | 13 | 车辆调度（Vehicle scheduling） |

### 数据库定义与连接

**数据引擎**：PostgreSQL **16+**，`JSONB` 类型存配置与**围栏数据**（支持 GIN 索引），应用层做空间判定；围栏数量少，不引入 PostGIS 空间类型，以降低复杂度（规模扩大后可按需迁移）。

**连接与库名**

| 项 | 说明 |
| --- | --- |
| 地址 | `127.0.0.1` |
| 端口 | `5432` |
| 库名 | `tmss_db` |
| 账号/密码 | `root/kexueguan723` |
| 编码 | `UTF8` / `zh_CN.UTF-8` |
| 时区 | 所有时间字段存 UTC（`TIMESTAMPTZ`），展示时由应用层转本地时间 |

**表命名与通用字段约定**（实施时可微调）：

- 表名、字段名：`snake_case`。
- 主键：自增 `BIGINT` 或应用侧雪花 ID，由你方统一；跨服务再考虑 UUID。
- 软删除、审计：若需要「后台留痕」，对关键业务表可预留 `deleted_at`、**操作人/操作时间**（或独立审计表）。
- 时间字段：统一 `created_at` / `updated_at`；轨迹点另见「定位」一节。

**逻辑表与职责（按域划分）**

下表在概念上覆盖前文「功能列表」中车辆、设备、人员、空间、规则、留痕、权限等需求；**未列出的细字段由你方在建表时补全**。

1. **车辆、设备、人员与绑定关系**  
   - `vehicle`：车辆主数据（牌照、载重/类型等你业务里需要的属性）。  
   - `device`：终端/模组身份（如 IMEI、型号、固件版本；与上报协议字段对齐）。  
   - `driver`：驾驶员（姓名、证号、所属车队 → **车队/组织**若拆表则 `org` / `fleet` 与关联表另建）。  
   - (暂不确定)`device_vehicle_driver_bind`：设备–车辆–驾驶员**绑定与解绑历史**（时间区间、操作者；满足「可解绑、可追溯」）。  
   *说明：若「车队维度」是强需求，可拆 `fleet`、`fleet_member` 等，避免在车辆表上堆标签。*

2. **定位、轨迹点与行程分段**  
   - `location_point`：高频点位（你协议中的 `t=g` 等）；建议包含：`device`/`vehicle` 外键、时间、经纬度、速度、海拔、质量/定位状态、原始报文 id（可选）。  
   - `track_segment`：按业务规则将连续轨迹切分为「段」（例如**停车超阈值**切下一段，与 README「停车 10 分钟切轨迹」对齐）；存起止时间、起止点、段内统计（可选）。  
   *说明：大表**分区/归档**策略（按日、按月、冷热分离）上线前再定；本章节只定逻辑。*

3. **空间与区域**  
   - `geo_zone`：元数据用常规字段（名称、类型、是否启用、备注等），**多边形/折线等几何用一条 `JSONB` 存**（例如 `coordinates: [[lng,lat],...]` 或与前后端约定一致的 GeoJSON 子集），便于和地图/配置导入导出对齐。`JSONB` 支持 GIN 索引，查询效率优于 `JSON`。  
   - 围栏**数量预计不多**：点是否在多边形内、与限速规则匹配等，在**服务层**用成熟几何库计算即可，无需在库内上空间索引。  
   - 区域**类型/用途**：装料、卸料、限行、急弯、单边桥/窄路、禁运/限速等，用类型字段 + 可选扩展 JSON 即可。  
   - 若需「同区域多套策略」（不同限速/时段），可拆 `zone_rule` 或用外键关联业务配置表，与「全局限速」分清楚即可。

4. **业务规则与运营参数**  
   - 装料/卸料**最短驻留**、**禁止运营**（分区域+时段）、**区域限速**、会车/调度相关参数等：可集中在 `business_config` 或**按子域拆表**（`speed_policy`、`operation_ban` 等），**待你方定稿规则模型后定表**。  
   - 与 `geo_zone` 的关联：业务规则里用**区域 id 外键**即可；**围栏形状仍只在 `geo_zone` 的 JSON 里**维护一份。

5. **状态、任务与事件留痕**  
   - **四种作业状态**、装料/卸料次数与任务统计：可设计 `work_session` / `load_unload_event` 等表（**状态机与字段**由你方定义）。  
   - **告警/违规/调度记录**：如超速、越界、限行/禁运、未报备驶离等，建议**事件类统一一张 `event` 或按类型分表**（查询模式决定）。  
   - 服务端**下行指令**可记 `command_log`（内容、时间、是否送达、可选手动操作者）。

6. **用户、角色与数据范围**  
   - `app_user`：系统登录账号，角色分三级（见下表），账号与车队绑定关系存于 `app_user.fleet_id`。  
   - `fleet`：车队实体，是**数据隔离**的基本单元；车辆通过 `vehicle.fleet_id` 归属于某一车队。  
   - 角色说明：

   | 角色 | 标识 | 说明 |
   | --- | --- | --- |
   | 管理者 | `manager` | 访问全部数据；修改系统设置时需**二次输入管理员密码**确认；大屏显示全部车辆 |
   | 车队长 | `fleet_captain` | 登记/管理**本车队**车辆与驾驶员，访问后台，大屏仅显示本车队数据；`fleet_id` 字段必填 |
   | 终端用户 | `terminal` | 对应使用硬件终端（ESP32）的驾驶员，通过设备 IMEI 标识，**无后台登录账号**；角色保留以备未来移动端扩展 |

   - 数据隔离由服务层统一执行：所有查询自动附加 `fleet_id` 过滤，车队长无法越权访问其他车队数据。  
   - 若后续需要更细粒度的权限（如某车队长只能查看特定车辆），可拆分 `fleet_vehicle` 关联表与 `user_permission` 表，当前阶段以 `fleet` 为单元足够。

7. **系统/应用参数**（与业务规则区分）  
   - `sys_config`：端口、环境开关、仅运维可改的参数；**与业务表分离**，避免和「装料最小时长」等运营数据混在一起。  
   - 可配合环境变量；**以谁为准**需团队约定，避免双源不一致。


完整建表 SQL 与表关系详见 [DATABASE.md](./DATABASE.md)。

*围栏与扩展配置**优先用 `JSONB`** 以降低库表与对接成本；其余表字段类型与约束由 `DATABASE.md` / 建表 SQL 定稿。*

### 后台功能设计与实现

> **坐标系约定**：设备端上报 **WGS-84** 坐标（GPS 原始），后台围栏存储与判定均使用 **GCJ-02**（国测局/火星坐标），所有空间判定前须先做 WGS-84 → GCJ-02 转换，避免围栏偏移。

#### 超速提醒

- **输入**：1 秒一次的定位简包（字段 `sp`，单位 km/h）。
- **判断条件**：优先匹配**区域限速**——若当前点在某一围栏内且该围栏配置了局部限速，以局部限速为准；否则使用**全局限速阈值**（默认 80 km/h，后台可调）。
- **动作**：向目标设备下发指令 `ws`，MCU 触发超速语音播报；同时向后台推送告警事件。
- **防抖**：同一设备同一限速来源，**10 秒内最多触发一次**，避免短时密集播报。

#### 超界提醒（限行区域）

- **输入**：1 秒一次 GPS 定位简包（需已定位，LBS 点不参与超界判定）。
- **判断条件**：若当前系统存在任意限行围栏，且当前点**不在任何一个限行围栏内**，则视为越界。
- **动作**：向目标设备下发指令 `wa`，MCU 触发越界语音播报；同时推送后台事件。
- **防抖**：同一设备 **10 秒内最多触发一次**。
- *说明：当前逻辑为"必须在任一围栏内才算合规"；若需要"只在特定围栏外才告警"，需扩展围栏的 `type` 字段加以区分。*

#### 急弯会车提醒

- **输入**：所有在线设备的实时定位。
- **判断条件**：后台标记急弯区域围栏，若区域内已有 **≥ 1 辆**车辆，后续进入该区域的新车辆触发提醒。
- **动作**：向**新进入**该区域的车辆下发指令 `vs`（车辆调度/来车提醒），同时可选通知已在区域内的车辆。
- **待明确**：是否双向提醒（区域内已有车与新进车均播报）；多车并发时的去重策略。

#### 单边桥、窄路来车语音调度

- **输入**：实时定位 + 单边桥/窄路区域围栏（区域较小，线段型或窄多边形）。
- **逻辑概述**：识别驶入方向与是否有对向来车，根据优先级规则下发「优先通行」或「停车等待」指令（`vs`）；同时后台留存调度记录。
- **待展开**：方向判定算法、优先级规则（如先到先行）、调度超时处理。

#### 作业状态识别与记录

基于车辆当前所在区域类型与速度，以**状态机**方式识别五种作业状态：

| 状态 | 触发条件 |
| --- | --- |
| **装料中** | 车辆在装料区内停留时长 ≥ 装料最短驻留阈值 |
| **卸料中** | 车辆在卸料区内停留时长 ≥ 卸料最短驻留阈值 |
| **空载运输** | 从装料区离开 → 驶向卸料区（或其它区域），无装载记录 |
| **重载运输** | 完成装料后离开装料区 → 驶向卸料区 |
| **未知** | 不满足以上任一条件（如在未标记区域行驶或停留） |

- 每次状态切换记录为一条 `work_session` 或 `work_event`，用于统计作业次数与时长。
- **待明确**：装料/卸料最短驻留阈值的默认值；空载/重载的区分依据（是否依赖前序状态）。

#### 时间与天气下发

设备端（ESP32 MCU）**主动发送请求**，服务端响应：

| 请求指令 | 服务端响应格式 | 说明 |
| --- | --- | --- |
| `rt` | `t{HHMMSS}`（如 `t143022`）| 返回服务器本地时间（6 位，时分秒），设备用于校准 RTC |
| `rw` | `w{temp}:{code}` （如 `w25:1`）| 返回天气（温度 + 天气码），数据来源 [wttr.in](https://wttr.in) |

- 天气数据在服务端**缓存**（默认 30 分钟），多设备请求共享缓存，减少外部请求。
- 设备端刷新周期约 **10 分钟**一次。
- 天气码（`code`）为服务端内部枚举（0~7），MCU 端按码播放对应动画/图标。
- **城市配置**：每个项目部署在固定地点，使用**单一城市**，城市名存于数据库配置中，无需多城市支持。

#### 欢迎语下发

设备上线并完成注册后，服务端根据**当前服务器时间**自动向设备下发对应欢迎语指令：

| 时段 | 指令 | 语音内容 |
| --- | --- | --- |
| 06:00 – 11:59 | `gm` | 早上欢迎语 |
| 12:00 – 17:59 | `ga` | 下午欢迎语 |
| 18:00 – 23:59 / 00:00 – 05:59 | `gn` | 晚上欢迎语 |

- 仅在**设备首次注册**（开机后第一次上线）时下发；断线重连不重复播报。

#### 轨迹录制与分段

每个已识别 IMEI 的设备维护一个**当前轨迹段**，定位点实时写入数据库，与数据库设计对应如下：

| 数据 | 对应数据库表 | 关键字段 |
| --- | --- | --- |
| 每个定位点 | `location_point` | `vehicle_id`、`recorded_at`、`lat`、`lng`、`speed`、`altitude`、`loc_type`（`gps`/`lbs`） |
| 一段连续轨迹 | `track_segment` | `vehicle_id`、`started_at`、`ended_at`、起止点坐标、段内统计（可选） |

内存中为每个在线设备保留最近 **300 个轨迹点**，供前端 SSE 断线重连时回放，消除断点。

**轨迹分段规则**：

轨迹分段的核心依据是**中断时长**，无论中断原因是停车还是掉线：

| 情况 | 中断时长 | 处理方式 |
| --- | --- | --- |
| 停车后恢复行驶 | < 阈值（10 分钟） | 续接当前 `track_segment` |
| 停车后恢复行驶 | ≥ 阈值（10 分钟） | 结束当前段，**写入新 `track_segment`** |
| 掉线后重连 | < 阈值 | 续接当前 `track_segment` |
| 掉线后重连 | ≥ 阈值 | 结束当前段，**写入新 `track_segment`** |

- 阈值默认 **10 分钟**，与功能列表第 12 条保持一致，后台可配置。
- 重连时，服务端通过**断线时刻与重连时刻的差值**判断是否超过阈值，而非仅凭连接状态续接。
- 停车判定：车速持续为 0 且无新定位点，持续时长超过阈值即切段。

> `server.py` 为早期 demo，上述逻辑在重构版本中实现。

#### 心跳监控与离线检测

- 设备端定期发送全零字节心跳包，服务端收到后更新设备的最后心跳时间戳。
- 后台每 **10 秒**扫描一次所有连接，**90 秒内未收到心跳**则标记为疑似离线，并向前端推送告警事件。


#### 手动指令发送

- 后台管理界面支持向**指定设备**（按连接 id 或 IMEI）手动下发任意 ASCII 指令。
- 常用于调试语音、远程触发特定播报，或下发调度指令 `vs`（会车/调度）。
- 指令发送记录实时推送到 SSE 事件流，供大屏/日志查看。

#### 用户与权限管理

- 采用**基于 Cookie Session** 的认证方式，Session 有效期 24 小时，收到请求自动续期。
- 角色与权限分三级：

  | 角色 | 标识 | 后台 | 大屏 | 车辆管理 | 系统设置 |
  | --- | --- | --- | --- | --- | --- |
  | 管理者 | `manager` | 全量访问 | 全部车辆 | 全部 | **需二次验证密码** |
  | 车队长 | `fleet_captain` | 本车队数据 | 仅本车队 | 本车队 | ✗ |
  | 终端用户 | `terminal` | ✗ | ✗ | ✗ | ✗ |

- **管理员二次验证**：`manager` 执行系统设置类高危操作时，前端弹出密码确认框，服务端重新校验当前用户密码后方可提交，无需独立 admin 账号。
- **数据隔离**：车队长登录后，服务层自动从 `app_user.fleet_id` 读取所属车队，所有数据查询附加 `fleet_id` 过滤，前端无法绕过。
- 支持后台新增、禁用用户，修改密码；初始默认管理员账号在首次启动时自动创建（角色 `manager`）。
- 大屏设计细节待后续补充，权限边界已在数据库层面通过 `fleet_id` 预留。

### 大屏设计

1. 不同状态车辆实时显示在主页，标记不同颜色：
   - 装料中 → 橙色 `#fa8c16`
   - 卸料中 → 绿色 `#52c41a`
   - 重载运输 → 红色 `#f5222d`
   - 空载运输 → 蓝色 `#1890ff`
   - 未知 → 灰色 `#8c8c8c`
2. 侧边栏展示在线车辆列表与今日告警列表
3. 围栏 `AMap.Polygon` 叠加层（颜色按围栏类型区分）
4. 收到告警事件时弹出 `ElNotification` 告警弹窗
5. （待完善）大屏右侧增加作业状态分布饼图、今日告警趋势折线图（ECharts）

### 历史轨迹查询（已完成）

- 按时间范围 + 车牌查询轨迹段列表，显示起止时间、距离、起止地址（逆地理编码）
- 点击轨迹行：地图绘制 `AMap.Polyline` + 起止点 `AMap.Marker`，300ms 过渡动画
- 轨迹回放控制：播放/暂停、速度档位（1× ~ 32×）、时间轴滑块
- 坐标系：GPS 定位点经 WGS-84 → GCJ-02 转换后显示，LBS 基站点直接使用
- 管理员（`manager`）可删除异常轨迹段（二次确认，事务删除段与定位点）
